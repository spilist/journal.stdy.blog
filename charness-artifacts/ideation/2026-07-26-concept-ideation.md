# Concept Ideation
Date: 2026-07-26

매일 쓰는 저널을 모바일에서 입력하고, 에너지 점수의 변동을 되돌아보는 개인용(n=1)
웹앱. 정본 형식은 [references/sample.md](../../references/sample.md)다.

판정 기준은 [cmanki AGENTS.md](../../../cmanki/AGENTS.md)의 `설계 취향`을 그대로
쓴다 — 같은 사람의 같은 취향이고, 이 리포에서 다시 유도할 이유가 없다.

## World Model

### 액터

한 명. 사용자 본인. 멀티유저·공유·유료화는 범위 밖이다.

### 현재 상태 (status quo) — 사용자 원문, 2026-07-26

> "내가 원래 메모장에 쓰던 거 더 편하게 쓰고, 에너지 레벨 추적을 잘 하고 싶어서 쓰는 거.
> **원래 메모장에 쓰고 복붙이었는데 복붙 안하고 싶은 거.**"

즉 지금 루프는 **메모장에 쓴다 → 저널 마크다운에 복붙한다**이고, 이 앱은 **그 복붙을
없애는 것**이다. 추측하지 말 것 — 이게 명시된 pain이다.

### 능력 실패 (capability failure)

1. **복붙.** 입력하는 곳과 저장되는 곳이 달라서 옮기는 손이 매번 든다. 그리고 옮기다
   말면 기록이 빈다 (`sample.md` 26-07-26 항목이 비어 있다).
2. **에너지 추적.** 점수가 텍스트 안에 문자열로 박혀 있어서 "지난 두 달 육체 에너지가
   어떻게 움직였나"를 볼 방법이 없다. 사용자가 **명시적으로 원한다고 말한 것**이므로
   투기적 기능이 아니다.

사용자가 [references/sample.md](../../references/sample.md)의 `## 행동` `- 메타`에 미리
같은 말을 써뒀다 — **매일 점수와 이유를 기록하고, 목표를 저널 쓸 때·회고할 때 계속
본다**는 것. (본문은 인용하지 않는다. AGENTS.md `사용자 데이터를 다룰 때`.)

### Product Posture

내부 도구(personal tool). 바이럴·배포·확장 표면은 비적용. **그리고 검증 의례도 비적용
(사용자, 2026-07-26: "이건 뭐 검증이고 뭐고 하룻밤 상관없고").** 전제를 트립와이어로
걸어두고 두 달 뒤 판정하는 식의 설계는 이 리포에서 하지 않는다 — 불편하면 그때 고친다.

### 엔티티

| 엔티티 | 설명 | 개수 |
|---|---|---|
| `Pinned` | **「잊지 않을 것」.** 날짜에 종속되지 않는 싱글톤. 제목을 앱이 모른다 (`D10`) | 1 |
| `Revision` | `Pinned`의 개정 스냅샷. 고친 날마다 1개 (`D11`) | 고친 날 수 |
| `Day` | 날짜 하나 (`YYYY-MM-DD`, KST) | N |
| `Energy` | `Day` × {인지, 정서, 육체} → 점수 + 이유 | 3N |
| `Log` | `Day` × {어제, 오늘} → 자유 텍스트 | 2N |
| `Conflict` | 동기화에서 진 블록의 사본. 사용자가 닫으면 사라짐 (`D12`) | 보통 0 |

`Day`의 표시 단위는 **블록 4개**다: 잊지 않을 것(접힘) · 에너지 · 어제 · 오늘.
**하루치 export에는 앞의 하나가 빠진다** (`D13`).

### 스테이지 (하루의 시간축)

`sample.md`를 읽으면 사용자가 저널을 **아침에** 쓴다는 게 드러난다 — 07-25의 `## 어제`가
07-24의 일이고, `## 오늘`이 그날의 계획이다. 그리고 07-25 `## 오늘`의 **마지막 줄만
그날 늦게 덧붙은 것**으로 읽힌다(앞줄들과 시제가 다르다).

1. **아침** — 에너지 점수 3개 + 어제 회고를 쓴다. 오늘의 계획을 쓴다.
2. **하루 중** — `## 오늘`에 줄이 추가된다. 여러 번.
3. **다음날 아침** — 전날의 `## 오늘`을 보고 이번 `## 어제`를 쓴다.
4. **주기적** — 대시보드에서 그래프를 본다.

## Verified Facts

`sample.md`에서 직접 읽히는 것만.

- **F1.** 정본 구조는 `H1 = 날짜(YY-MM-DD)` / `H2 ∈ {에너지, 어제, 오늘}`이고,
  에너지 아래는 `- {차원}: {점수}. {이유}` 고정 3줄이다 (07-25 항목).
- **F2.** `# 2026 하반기 목표`는 날짜가 아닌 H1이고, 아래 H2가 `에너지`·`행동`이다.
  즉 **H2 이름 `에너지`가 목표 블록과 날짜 블록에서 서로 다른 것을 뜻한다.**
- **F3.** 점수 관측치는 `7`, `7`, `5`. 최소 10점 척도로 보인다 — 5점 척도라면 `5`가
  만점인데, 그 줄의 이유가 부정적 서술이라 만점일 리 없다.
- **F4.** **기록 시각이 점수에 영향을 준다는 걸 사용자가 본문에 직접 써뒀다**
  (`sample.md` 07-26 `## 오늘`. 본문은 인용하지 않는다).
  → 요구사항의 `updatedAt`은 장식이 아니라 **점수의 교란변수 기록**이다.
- **F5.** 사용자 스택은 이미 정해져 있다 (cmanki): Svelte 5 + Vite + Cloudflare
  (wrangler, custom domain), TypeScript 아님(JSDoc + `checkJs`), Prettier 없음,
  `node --test`, 의존성 최소.

## Assumptions

**계측하거나 트립와이어를 걸지 않는다.** 불편하면 사용자가 말한다. 아래는 "이게 틀리면
무엇을 고치면 되는지" 미리 적어두는 용도일 뿐이다.

- **A1.** 10점 척도의 해상도가 실제로 쓰인다. 틀리면 → 5점으로 내린다. 되돌릴 수 있다.
- ~~**A2.** 그래프를 실제로 본다.~~ **철회 (2026-07-26)** — 사용자가 "에너지 레벨 추적을
  잘 하고 싶어서"라고 명시했다. 전제가 아니라 요구사항이다.
- ~~**A3.** 오프라인 입력이 없어도 견딜 만하다.~~ **철회 (2026-07-26)** — 오프라인이
  기본이다. `쟁점 10` 참조.
- **A4.** 사용자가 push 버튼을 실제로 누른다. **`D3` 이후 남은 유일한 데이터 유실
  경로다** — 안 누르면 폰 브라우저 저장소에만 산다. 그래서 계측 대신
  **미동기화 배지를 눈에 띄게** 두는 걸로 대응한다 (`D17`).

## 핵심 쟁점

### 쟁점 1 — 정본을 텍스트로 둘 것인가, 구조화할 것인가 (**가장 상류**)

나머지 설계가 여기서 갈린다. cmanki는 "정본은 텍스트, 파생은 버리고 재계산 가능"으로
확립했는데, 이 앱의 요구가 그것과 충돌하는 것처럼 보인다:

- "원터치 라디오 버튼으로 점수 입력" → 구조화 필드
- "에너지 변동 그래프" → 점수가 숫자여야
- "블록별 updatedAt" → 블록이 레코드여야
- "export하면 마크다운" → 텍스트 산출

| 안 | 정본 | 문제 |
|---|---|---|
| **A. 순수 텍스트** | `(date, section, text, updatedAt)` 4열. 점수는 `^(\d+)\.`로 파싱 | **비직교성.** 라디오 버튼과 텍스트 편집이 **같은 문자열을 두 방식으로 건드린다.** cmanki 2항이 최악의 실패 모드라 부르는 바로 그것. 그리고 사용자가 형식을 한 번 깨면 그래프가 조용히 빈다 |
| **B. 전면 구조화** | 에너지·로그 모두 필드로 분해 | `## 어제`/`## 오늘`은 진짜 자유 텍스트라 분해할 게 없다. 없는 구조를 만드는 것 |
| **C. 경계로 나눔 (추천)** | 에너지 = `(date, dim, score, reason, scoredAt)` / 로그·목표 = `(date, kind, text, updatedAt)` | 정본이 둘로 갈리는 것처럼 보인다 |

**C를 추천한다. 근거는 cmanki 원칙과 어긋나지 않는다:**

cmanki가 텍스트를 정본으로 삼은 이유는 "구조는 사람이 손으로 확정하고, 파생은 언제든
재계산"이었다. 그런데 cmanki도 **한 가지는 필드로 저장한다** — 승인/거부 로그다. 이유가
`store.js` 주석에 그대로 있다:

> "Approve/reject decisions are the ONE thing here that is not recomputable from
> the text — a human judgement, gone forever if not written down."

**에너지 점수가 정확히 그 지위다.** 계산으로 복원할 수 없는 사람의 판단이다. 그러니 점수를
필드로 두는 건 cmanki 원칙의 위반이 아니라 **적용**이다. 반대로 `## 어제`/`## 오늘`은
자유 산문이므로 텍스트 그대로가 정본이다.

그리고 C는 쟁점을 하나 없앤다 — **점수는 라디오로만, 이유는 텍스트로만** 편집되므로
표면이 겹치지 않는다. A에서 생기는 비직교성이 애초에 발생하지 않는다.

**반대 의견 (기록용).** C가 틀릴 수 있는 지점: 나중에 4번째 차원(예: `사회`)을 추가하거나
`## 어제`/`## 오늘` 말고 다른 섹션을 만들고 싶어지면, A는 텍스트만 고치면 되는데 C는
스키마를 건드려야 한다. 차원 집합은 `dim`을 문자열 컬럼으로 두면 완화되지만 UI는 여전히
고정 3개를 가정한다. **하반기(6개월) 안에 형식을 바꿀 생각이 있다면 A가 낫다.**

### 쟁점 2 — `## 어제`와 전날의 `## 오늘`이 같은 날을 두 번 기록한다

`sample.md`에서 07-25의 `## 오늘`과 07-26의 `## 어제`는 **둘 다 07-25에 대한 서술**이다.
비직교성으로 보인다.

**하지만 없애면 안 된다.** 시점이 다르면 다른 정보다 — `## 오늘`은 실시간 기록이고
`## 어제`는 하루 지난 뒤의 압축·해석이다. 회고에 가치가 있으니 두 개 다 남긴다.

**대신 기능 0개로 완화한다** (cmanki 1항·4항): 07-26의 `## 어제` 블록을 편집할 때
**07-25의 `## 오늘` 내용을 읽기 전용으로 옆/위에 띄운다.** 새 기능이 아니라 이미 있는
데이터를 다른 자리에 보여주는 것뿐이고, "다시 떠올려 쓰기"가 아니라 "보면서 회고하기"가
된다.

### 쟁점 3 — 인증. 사적인 데이터가 공개 URL에 올라간다

이 저널에는 아내·딸·부모님·건강 상태·회사 채용 얘기가 들어있다. 그게 공개 도메인에
붙은 D1에 평문으로 앉는다. "회원가입 없이 정해둔 아이디/비번"이라는 요구는 **UX 요구**로
읽고, 구현은 그보다 강하게 가는 게 맞다.

| 안 | 앱이 지는 부담 |
|---|---|
| **자체 ID/PW** | Worker Secret에 비번 해시(scrypt) · 서명된 세션 쿠키(HttpOnly/Secure/SameSite) · 무차별 대입 rate limit · 세션 만료. **직접 짜야 하는 보안 코드가 생긴다** |
| **Cloudflare Access (추천)** | **0줄.** 앱 앞단에서 Zero Trust가 막는다. 이메일 OTP 또는 Google 로그인, 허용 이메일 1개만 등록. 무료 티어. Worker는 `Cf-Access-Jwt-Assertion`만 신뢰하면 된다 |

cmanki 9항(적을수록 좋다) · 10항(결에 맞는 디자인)이 Access를 가리킨다. **인증을 짜지
않는 게 가장 적은 코드다.** 사용자 요구인 "아이디/비번"과 다르지만, 조합안으로 먼저
제시한다 (cmanki `요청을 받는 방식` 2항).

**Access의 단점**: 세션 만료 시 OTP를 받아야 해서 폰에서 한 번씩 귀찮다(만료 기간은
최대 1개월까지 설정 가능). 그리고 Cloudflare에 로그인 이벤트가 남는다.

E2E 암호화는 오버킬로 본다 — 폰에서 매번 복호화 키를 넣어야 하면 복붙보다 불편해진다.
**복붙을 없애는 게 목적인데 더 큰 마찰을 만들면 본말이 전도된다.**

### 쟁점 4 — 점수 척도와 모바일 터치 타깃

10점 척도를 가로 스트립으로 깔면 폰 폭(~360px)에서 버튼 하나가 ~34px다. 권장 최소
터치 타깃 44px에 못 미쳐서 **오터치가 난다.** 원터치 입력이 요구사항인데 오터치가 나면
요구사항이 무너진다.

- **10점 유지 + 2행 배치 (5×2)** — 과거 데이터 호환, 터치 타깃 확보, 대신 세로 공간을
  먹고 5와 6 사이에 시각적 단절이 생긴다
- **10점 유지 + 1행, 높이를 56px로** — 폭 34px여도 세로가 넉넉하면 실사용 오터치가
  크게 줄어든다. 가장 적은 변경
- **5점으로 축소** — 터치는 가장 쉽지만 `sample.md`의 7·5가 무의미해지고 `A1`을 미리
  포기하는 것

가장 적은 변경은 두 번째다. `A1`이 깨지면 그때 5점으로 내린다 — 되돌릴 수 있게
유지한다(cmanki 12항).

### 쟁점 5 — `updatedAt`의 정확한 의미

`F4` 때문에 이건 중요한 필드다. 두 가지가 섞여 있다:

- **에너지**: "점수를 매긴 시각"이 의미 있다. 이유 문장을 오타 고치려고 열었다고 시각이
  갱신되면 `F4`의 해석 가치가 사라진다 → **`scoredAt`은 점수 값이 실제로 바뀔 때만
  갱신한다.**
- **어제/오늘**: 단순히 "마지막으로 손댄 시각"이면 충분하다.

그리고 자동저장을 쓰면(모바일에서 저장 버튼 누르기 전에 앱을 닫아 유실되는 걸 막아야
하므로 자동저장이 맞다) **내용이 실제로 변했을 때만** 시각을 갱신한다.

### 쟁점 6 — 날짜 경계와 타임존

사용자는 새벽 루틴이 있다. 서버(Worker)는 UTC로 돈다. **KST를 고정하지 않으면 오전 9시
이전에 쓴 기록이 전날로 붙는다** — 새벽에 쓰는 사람에게 치명적이다. 날짜 계산은 전부
`Asia/Seoul` 고정. 새벽 2시에 쓴 건 그 전날인가 그날인가는 **사용자가 날짜를 직접 옮길 수
있으므로 정책을 강제하지 않는다** — 기본값만 KST 캘린더 날짜로 둔다.

### 쟁점 7 — `H2 에너지`의 이름 충돌 (`F2`)

`# 2026 하반기 목표 > ## 에너지`(이상적 상태 서술)와 `# 26-07-25 > ## 에너지`(점수+이유)는
이름이 같고 뜻이 다르다. 파서와 UI가 **H1이 날짜인지 아닌지로** 분기해야 한다. 목표는
날짜 없는 싱글톤이므로 애초에 다른 테이블/화면으로 두면 충돌이 사라진다. 목표 블록의
내부 구조(에너지/행동)는 **파싱하지 않고 텍스트 한 덩어리로 둔다** — 접어놨다가 읽기만
하는 블록에 구조가 필요 없다 (cmanki 9항).

### 쟁점 8 — Export, 그리고 Import

- 하루치 export: `H1 날짜` + `H2 에너지/어제/오늘` 조립. 클립보드 복사.
- **전체 export도 같은 함수에 날짜 범위만 다르게 준 것**이므로 기능이 1개다. 개인
  데이터의 소유권 측면에서 넣는 게 맞다.
- **Import는 별개 기능이지만 지금 필요하다.** `sample.md`의 과거 기록을 넣어야 첫날부터
  그래프에 볼 게 있다. **이게 마지막 복붙이다.** 파서는 export의 역함수라 비용이 작고,
  일회성으로 쓰고 UI에서 빼도 된다.

### 쟁점 9 — 그래프를 무엇으로 그리나

라인 3개, 축 2개, y가 1~10 고정. **직접 SVG로 그리는 게 라이브러리보다 적다.**
cmanki도 의존성은 dagre 하나뿐이다. Chart.js/D3를 넣으면 번들과 API 학습이 붙는데
얻는 게 없다.

- 결측일(점수 없는 날)은 **선을 끊는다.** 이어버리면 안 쓴 날이 보이지 않게 되는데,
  안 쓴 날 자체가 신호다.
- 터치 인터랙션: 폰에는 hover가 없다. 탭 → 툴팁(그날 3차원 이유 전부) → 다시 탭하면
  그날로 이동. **"그날로 이동"은 이미 있는 날짜 이동 기능이라 조합으로 공짜다** —
  그래프가 인출 통로가 되는 지점이다 (cmanki 15항).
- 기본 창: 모바일 폭에서 30일 정도가 한계. 하반기 전체는 가로 스크롤.

### 쟁점 10 — 오프라인 우선 + 수동 동기화 (**사용자 결정, 2026-07-26**)

> **사용자**: "기본으로 오프라인 액세스 지원. 버튼 눌러서 동기화."

이전 판은 오프라인을 S3로 미뤘는데 **뒤집혔다.** 그리고 이 결정은 두 가지를 바꾼다:

**바뀌는 것 1 — 정본의 위치.** 로컬(IndexedDB)이 **작업 정본**이고 D1은 **동기화 대상**이다.
앱은 네트워크 없이 완전히 동작한다. 이건 cmanki `자동화 금지` 2항("상시 자동 X 금지,
**명령형 버튼만 허용**")과 같은 형태다 — 자동 동기화가 조용히 도는 대신 사람이 누른다.

**바뀌는 것 2 — 충돌 해결이 필요해진다.** 단일 사용자지만 폰과 데스크톱 두 기기가 생기면
같은 블록을 양쪽에서 고칠 수 있다. **다행히 여기서는 싸다** — 블록이 작고 동시 편집이
사실상 없으므로 **블록 단위 last-write-wins**로 충분하고, **충돌 해결 키가 이미 요구사항에
있다(`updatedAt`)**. 요구사항 하나가 공짜로 두 역할을 한다.

- 동기화 = 블록 목록 push/pull, 각 블록은 `updatedAt`이 큰 쪽이 이긴다.
- 진 쪽 내용을 **버리지 말고** 로컬에 `conflict` 사본으로 남긴다. 저널은 다시 못 쓴다.
- 삭제는 없다(블록은 비어 있을 수 있을 뿐 사라지지 않는다) → tombstone 불필요.

**새로 생긴 위험 — `A4`.** 수동 동기화의 대가는 **안 누르면 폰에만 있다**는 것이다.
브라우저 저장소는 용량 압박 시 evict될 수 있고, 폰을 잃으면 끝이다. 완화책:

- `navigator.storage.persist()` 호출 (PWA 홈 화면 추가 시 대개 승인된다)
- **미동기화 블록 수를 항상 보이게 한다.** 배지가 0이 아니면 눈에 띄어야 한다.
  이건 자동 동기화가 아니므로 사용자 결정과 충돌하지 않는다.
- 앱을 열 때 **온라인이면 pull은 자동, push는 버튼**으로 나누는 것도 가능하다.
  pull은 로컬을 덮어쓰지 않으므로(LWW) 위험이 없다. **다만 이건 "버튼 눌러서 동기화"의
  해석 문제라 사용자 확인이 필요하다.**

### 쟁점 11 — 오프라인 PWA와 Cloudflare Access는 궁합이 나쁠 수 있다 (**신규**)

쟁점 3에서 Access를 추천했는데, 오프라인 우선 결정이 **그 추천을 약화시킨다.**

Access는 엣지에서 모든 요청을 가로채고, 세션이 만료되면 **401이 아니라 로그인 페이지로
302 리다이렉트**한다. 그러면 동기화 버튼을 눌렀을 때 서비스워커/`fetch`가 JSON 대신
HTML을 받는다. 처리는 가능하지만(리다이렉트를 감지해 "다시 로그인" 안내) **앱이
인증을 0줄로 모른 척한다는 Access의 장점이 사라진다.**

- Access를 쓴다면: 동기화 엔드포인트에서 **HTML 응답이 오면 로그인 필요**로 처리하는
  분기를 넣는다. 코드 몇 줄이지만 "0줄"은 아니다.
- 자체 인증을 쓴다면: 401이 깔끔하게 오고, 세션 쿠키를 길게(예: 180일) 두면 폰에서
  재로그인이 사실상 없다. 대신 비번 해시·세션 서명·rate limit을 직접 짠다.

**두 안의 비용 차이가 오프라인 결정 때문에 줄었다.** 여전히 Access가 약간 앞선다고
보지만 확신은 낮아졌다 — Q2에서 사용자가 판단할 지점이다.

### 쟁점 12 — 배포 (**사용자 결정, 2026-07-26**)

> **사용자**: "배포는 이 리포명으로 내 개인 도메인 클라우드플레어에 할 것."

- 도메인: **`journal.stdy.blog`** 커스텀 도메인. `stdy.blog` 존이 이미 Cloudflare에
  있다 — [`~/stdy.blog/wrangler.jsonc`](file:///home/hwidong/stdy.blog/wrangler.jsonc)가
  `www.stdy.blog`를 `custom_domain: true`로 쓰고 있다. **도메인 확인이 끝났다.**
- `.env`는 `~/stdy.blog/.env`에서 복사했다(내용 미열람). `.gitignore`에 이미 있다.
- **D1 사용 선례가 같은 계정에 있다** — `stdy-blog-db`. 스키마 파일 + `wrangler d1 execute`

- `workers_dev: false`로 두어 `*.workers.dev`로는 열리지 않게 한다 (`stdy.blog` 선례).
  사적 데이터라 노출 표면을 하나 줄이는 게 맞다.
- 빌드/배포 스크립트는 cmanki 쪽(`vite build` + `wrangler deploy`)이 더 가깝다 —
  `stdy.blog`는 SvelteKit·pnpm이지만 이 앱은 cmanki와 같은 소형 SPA다.

## Decisions (사용자 확정, 2026-07-26)

- **`D1` — 정본은 경계로 나눈다 (`Q1` = 안 C).**
  ```
  energy  (date, dim, score, reason, scoredAt)   dim ∈ {인지, 정서, 육체}
  log     (date, kind, text, updatedAt)          kind ∈ {어제, 오늘}
  pinned  (text, updatedAt)                      싱글톤
  revision(day, text, createdAt)                 D11에서 추가
  ```
  **로컬(IndexedDB)이 작업 정본이고 D1은 동기화 대상이다.** export는 이 셋에서
  결정론적으로 조립한다. 점수는 라디오로만, 이유는 텍스트로만 편집된다.
  **반대 의견은 `쟁점 1`에 기록돼 있다** — 하반기 안에 형식을 바꾸고 싶어지면 이 결정이
  비싸진다.
- **`D2` — 인증은 Cloudflare Access (`Q2`).** 허용 이메일은 **`bae.hwidong@gmail.com`
  하나** (사용자 확정 2026-07-26). 앱은 인증 로직을 짜지 않는다. **단 `쟁점 11`의 대가를 진다** — 동기화 응답이 JSON이 아니면(=로그인
  리다이렉트 HTML) "다시 로그인" 상태로 전환하는 분기가 필요하다. 이건 회피 불가이므로
  `spec`에서 계약으로 못박는다.
- **`D3` — pull은 자동, push는 버튼 (`Q7`).** 앱을 열 때 온라인이면 서버 변경분을
  당겨온다. 블록 단위 LWW라 **로컬의 더 새로운 내용은 절대 덮이지 않는다.** 올리는 건
  사람이 누른다. 불변식 "동기화는 사람이 누른다"는 **push에 적용된다** — pull은 로컬을
  파괴하지 않으므로 자동이어도 결정과 충돌하지 않는다.
- **`D4` — S1에 그래프를 넣지 않는다 (`Q3`).** 아래 슬라이스 참조.
- **`D5` — 폰과 데스크톱 둘 다 쓴다.** 따라서 **충돌 처리가 실제로 필요하다** —
  블록 단위 LWW로 이기는 쪽을 정하고, **진 쪽은 `conflict` 사본으로 보존**한다
  (불변식 3: 사용자가 쓴 글자를 잃지 않는다). 충돌이 났다는 걸 알리는 UI가 S1에
  들어간다. 충돌 처리가 "확인 필요"에서 "필수 구현"으로 올라갔다.
- **`D6` — 로컬 저장은 자동, 서버 push만 버튼.** 타이핑이 ~1초 멈추면 로컬에 쓴다.
  **불변식 2("동기화는 사람이 누른다")는 서버 push에만 적용된다** — 로컬 자동저장은
  동기화가 아니라 유실 방지이므로 충돌하지 않는다. `updatedAt`은 **내용이 실제로
  변했을 때만** 갱신한다(공백만 바뀌거나 포커스만 옮긴 건 제외). 에너지 `scoredAt`은
  `D15`대로 점수 값이 바뀔 때만 별도로 갱신한다.
- **`D7` — 점수는 10점, 1행, 높이 56px (`Q4`).** 폭 34px이라 권장 터치 타깃에 못
  미치지만 세로를 키워 상쇄한다. `A1`이 깨지면 5점으로 내린다.
- **`D8` — 「어제」블록 위에 전날의「오늘」을 읽기 전용으로 띄운다 (`Q6`).**
  기능 추가 0개. 이미 있는 데이터를 다른 자리에 보여주는 것뿐이다.
- **`D9` — Access 세션은 1개월.** 매일 쓰는 도구라 로그인 마찰을 최소화한다. 폰을
  잃으면 Access 대시보드에서 세션을 즉시 해지한다.
- **`D10` — 고정 블록은 「하반기 목표」가 아니다.** 사용자 원문: *"목표 자체가 계속
  수정될 거라 기간별이 아니라 **변경내역**이 필요. 위키처럼. 그러니까 '하반기 목표'로
  고정할 필요 없음. **잊지 않을 것** 정도이려나."*
  - **기간(`period`) 키는 넣지 않는다.** 기간별 이력이 아니라 **한 문서의 개정 이력**이다.
  - **제목을 코드에 박지 않는다.** 블록 텍스트가 자기 제목(`# ...`)을 포함하면 앱이
    이름을 모르고, 사용자가 언제든 바꿀 수 있다 (cmanki 9항).
  - **개정 이력이 새 요구사항으로 추가됐다.** `D6`(자동저장)과 충돌하므로 스냅샷
    시점 정책이 필요하다 → `D11`.
- **`D11` — 개정 스냅샷은 하루에 1개.** 그날 처음 손대는 시점에 **직전 내용을** 밀봉한다
  (KST 날짜 기준). 하루 종일 고쳐도 스냅샷은 1개이므로 자동저장(`D6`)과 충돌하지 않고,
  사람이 누를 버튼도 늘지 않는다. 고친 날만 타임라인에 줄이 생긴다.
- **`D12` — 충돌은 블록 안에 접힌 사본으로 붙인다.** 진 쪽 내용이 해당 블록 아래
  `▸ ⚠ 충돌 사본 (기기, 시각)`으로 접힌 채 붙는다. 펼쳐서 쓸 문장만 옮기고 닫으면
  사라진다. **push를 막지 않는다** — 이동 중에 막히면 거슬리고, 불변식 3(글자를 잃지
  않는다)은 사본 보존으로 이미 충족된다.
- **`D13` — Export는 하루치와 전체 둘 다.** 사용자 원문: *"전체 좋고, 하루치도 그 하루에
  대해 sample.md 처럼 (**목표 부분 빼고**) 마크다운으로 조립되어 복사되어야 함."*
  - 하루치 → 클립보드. `# 26-07-25` + `## 에너지` / `## 어제` / `## 오늘`.
    **고정 블록은 포함하지 않는다.**
  - 전체 → `sample.md` 형식 마크다운 다운로드.
  - **같은 조립 함수에 날짜 범위만 다르게 준 것**이므로 기능은 1개다.
- **`D14` — 그래프 기본 창은 최근 30일, 기간 조정 가능.** 사용자 원문: *"기본은 최근
  30일. 기간 조정 가능('1개월 더'). 전체 버튼도 있고."* → 「1개월 더」로 창을 넓히고,
  「전체」로 한 번에 펼친다. 30일 기본은 폰 폭에서 점이 안 붙는 한계선이다.

### 사용자에게 묻지 않고 확정한 것 (근거는 위 쟁점들)

- **`D15`** — `scoredAt`은 점수 **값이 실제로 바뀔 때만** 갱신한다 (`F4`, 쟁점 5).
  이유 문장 오타를 고쳤다고 갱신하면 해석 가치가 사라진다.
- **`D16`** — 날짜 계산은 전부 `Asia/Seoul` 고정 (쟁점 6). Worker가 UTC라 안 박으면
  KST 09시 이전 기록이 전날로 붙는다. 새벽에 쓰는 사용자에게 치명적이다.
- **`D17`** — `navigator.storage.persist()`를 호출하고 **미동기화 블록 수를 상시
  노출**한다 (`A4`). push를 안 누르는 게 유일하게 남은 데이터 유실 경로다.
- **`D18`** — Worker는 `Cf-Access-Jwt-Assertion`을 검증하고, `workers_dev: false`로
  둔다 (`D2`, 쟁점 11). Access는 커스텀 도메인 앞만 막으므로 이게 없으면 우회된다.
  그리고 **동기화 응답이 JSON이 아니면**(=로그인 리다이렉트 HTML) 재로그인 상태로
  전환한다.
- **`D19`** — 그래프에서 점수 없는 날은 **선을 끊는다.** 이으면 안 쓴 날이 안 보이는데,
  안 쓴 날 자체가 신호다.
- **`D20`** — `dim`은 문자열 컬럼으로 열어두되 UI는 3개를 가정한다. `D1`의 반대
  의견(차원 추가가 비싸진다)을 스키마 쪽에서만 미리 완화해 둔다. **UI를 일반화하지는
  않는다** — 쓰지 않을 유연성이다.
- **`D21` (2026-07-28)** — 세 차원의 점수 스트립 위에도 **전날의 점수·이유를 읽기
  전용으로 띄운다.** `D8`을 에너지에 그대로 확장한 것이고, 기능 추가 0개다 — 이미
  저장된 값이 매기는 자리 옆에 놓일 뿐이다. 점수는 절대값보다 **어제 대비**로 읽히는데
  (그래프를 펼치거나 날짜를 옮겨야만 보였다), 매기는 순간에 그 비교가 없으면 그때그때
  기준이 흔들린다.
  - **반대 의견**: 전날 점수가 보이면 **닻(anchoring)**이 된다. "어제 7이었으니 오늘은
    6쯤" 하고 실제 상태가 아니라 어제의 숫자에서 출발할 수 있다. 그러면 추세 자체가
    평평해지고, 에너지 추적(앱의 목적 2)이 측정하려던 게 지워진다. 불편하면 사용자가
    말한다 — 되돌리는 건 이 블록을 지우는 것 하나다.
  - 이유는 **한 줄로 자른다.** 세로로 자라면 점수 스트립이 아래로 밀려 매기는 동작이
    멀어진다 (`P-2`와 같은 우려).

그래프를 S1에서 빼는 이유는 **입력이 먼저이기 때문**이지 덜 중요해서가 아니다 —
사용자가 명시적으로 원한 두 가지 중 하나다.

**동기화는 마지막에 붙인다.** 로컬만으로 도는 앱을 먼저 완성하면 그 시점에 이미
**복붙이 사라진다** — 목적이 달성된 상태다. D1 push/pull은 그 위에 얹는 것이므로
중간에 멈춰도 쓸 수 있는 물건이 남는다.
