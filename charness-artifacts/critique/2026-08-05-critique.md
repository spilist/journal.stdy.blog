# 온라인 복귀 동기화 경계 수정
Date: 2026-08-05

## Decision Under Review

`online`·`visibilitychange`가 서버 pull 전에 IndexedDB를 다시 읽도록 lifecycle 경로를
`Journal.lifecyclePull()`로 모으고, 초기 load·reload 실패·이벤트 경합을 한 큐에서 다룬다.

## Failure Angles

- 다른 탭의 미동기화 로컬 판본을 메모리가 모르고 서버 값으로 덮는가 — `App.svelte`와
  `state.svelte.js`의 순서를 대조하고 하네스로 재현했다.
- 초기 로드 중 복귀 이벤트가 pull을 먼저 실행하거나, reload 실패 뒤 원격 값을 적용하는가 —
  load promise·성공 boolean·직렬화 경계를 검토했다.
- 수정이 과해져 새 자동 동기화나 브라우저 E2E를 끌어들이는가 — 기존 pull/수동 push와
  IndexedDB 대역 안에서만 고정하는 counterweight를 적용했다.

## Counterweight Pass

- 첫 문제는 강한 증거의 P1 데이터 유실 경로다. 단순 연결은 초기 load와 reload 실패를
  안전하게 다루지 못하므로 lifecycle 큐까지는 `act-before-ship`이다.
- BroadcastChannel, versionchange 처리, 인증 브라우저 E2E, major 의존성 업그레이드는
  이번 결함을 닫는 데 필요하지 않아 `valid-but-defer` 또는 `over-worry`다.
